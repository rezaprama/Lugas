## [0.3.0] — 2026-10-22

### Changed

- **Renamed RhetoriLex to Lugas.** Package `lugas`, command `lugas`, skill `skills/lugas`,
  site `https://rezaprama.github.io/Lugas/`. Compatibility: `rhetorilex` command,
  `python -m rhetorilex`, and `import rhetorilex` (with `DeprecationWarning`) remain;
  `RLX-*` IDs, dataset file names, and format identifiers are unchanged; per-route
  redirect pages for the old Pages path are generated by `scripts/build_redirect_site.py`.
- Skill rewritten around an explicit job scope (correct, edit, paraphrase, translate,
  summarise), protected-element lock, Indonesian output, and lean replies.
- Workbench: job and output-language selectors (Indonesian output now possible; the old
  "Indonesian-friendly English" mode only produced English), compact injection-safe
  prompt (−27% characters), paste-and-check for prompt-only use, 90 s timeout, cancel,
  truncation and CORS messages.
- Removed the 3-calls-per-day browser counter: it only limited the user's own endpoint
  and quota and protected no shared cost.

### Added

- Installable PWA workbench (prompt-only mode, BYO endpoint) with English and Indonesian
  routes; the static site has 62 localized routes.
- Offline meaning guard (`lugas check`, `skills/lugas/scripts/guard.py`, `docs/guard.js`):
  numbers with decimal comma, statistics, citations, quotations, Indonesian/English
  negation, hedges, association vs causation, direction, scope, non-significance, and
  instruction-like text. No 40-item cap. Browser and Python agree on all 112 benchmark items.
- Indonesian lint (`lugas lint`) for common EYD V/KBBI slips and English calques.
- `references/bahasa-indonesia.md`: original Indonesian rules and over-correction list;
  principles inspired by naskah-id (MIT), text written independently.
- Benchmarks: meaning-guard dev and independently written held-out fixtures; model-run
  comparison (plain prompt, skill v0.2, skill v0.3) with blind LLM judging. See
  `docs/benchmarks.md`.
- Naming research and migration record: `docs/brand/naming-2026-10.md`.

### Fixed

- Documentation referenced a nonexistent `show` command and pattern ID; now `explain RLX-QUA-001`.
- Service worker cache name now changes with assets; offline fallback respects the page language.

## [0.2.0] — 2026-08-19

### Added

- Expanded the original catalog to 96 entries across 24 rhetorical functions with
  versioned Phase 2 schema, taxonomy, editorial, translation, and benchmark assets.
- Added 144 original writing skills (64 academic, 66 scientific, and 14
  paraphrasing) across 11 substantive groups.
- Published 60 localized static routes: 30 English and 30 Indonesian.
- Timestamped GitHub repository, topic, keyword, and recursive-tree discovery datasets.
- Methodology-led discovery research and GitHub landscape reports with interpretation
  gates and explicit measurement limits.
- English/Indonesian README parity for features, safety boundaries, research citations,
  creator information, and discovery evidence.

### Changed

- Positioning now describes RhetoriLex as an offline, evidence-calibrated rhetorical-move
  and academic-writing system for researchers, editors, and AI agents.
- Package and citation metadata now identify Reza Prama Arviandi, version 0.2.0, project
  URLs, and expanded discovery terms.

### Research and provenance

- GitHub values are dated repository-index or metadata snapshots, never represented as
  search volume, demand, adoption, or quality.
- Google Trends Worldwide and Indonesia direct measurements remain explicit `null`
  because no reproducible official export was available; no proxy value was invented.
- No third-party repository content was copied. Landscape work records public metadata,
  commit-pinned file counts, and original annotations only.

## [0.1.0] — 2026-08-19

### Added

- Initial offline Python catalog, search, filtering, suggestions, and CLI surface.
- Original evidence-aware starter catalog, taxonomy, and claim-strength contract.
- Compact `rhetorilex` Agent Skill with progressive-disclosure references.
- Schema/data validation, synthetic evaluation cases, and deterministic checks.
- Static documentation/explorer and contributor-facing project documentation.
- Aggregate XLSX audit and clean-room migration decision with zero source promotion.
- Source registry, provenance policy, third-party notices, and REUSE license mapping.
- Governance, conduct, security, contribution, citation, and six-month roadmap files.

### Security and integrity

- Core retrieval operates locally without an API key.
- Restricted workbook, private staging data, source corpora, and manuscript content are
  excluded from version control and release artifacts.
- Canonical entries require original-editorial provenance and explicit evidence/claim
  metadata.
